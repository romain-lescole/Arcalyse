📖 Help — Relation Map · Capella

Arcalyse — your Capella model, inside and out

Standalone application (a single HTML file) to explore, analyse, check and export a Capella / ARCADIA model without opening Capella. The .capella file is read locally in the browser.

Opening a model

  1. Drag and drop a .capella file anywhere in the window, or click 📂 .capella file… on the home screen (or 📁 File › 🔷 Open a Capella model). 📁 Project folder… (or 📁 File › 📁 Open the project folder…, or a dropped folder, in Edge / Chrome) loads the .capella and its .aird diagrams together; if it contains several models, you choose which one.
  2. The model is analysed, then the project 🏠 Home view opens automatically (information, checklists, review plans, whiteboards, review packages).
  3. ⚡ Chains is no longer pinned by default: it is in the 📡 Flows & interfaces menu (📌 in ☰ to pin it again).
  4. To change model, simply drop another file (it replaces the displayed model).
  5. For a new version of the same model: 📁 File › 🔄 Load a model update shows the delta first, then updates after confirmation (see 🔄 Watch).
  6. New version of Arcalyse: 📄 Work project (.html)… on the welcome screen (or 📁 File › 📄 Open a work project, or the page dropped on the window) carries over a page saved with an earlier version (2.1 or later): model, diagrams, review, home, dashboards, ▤ Table, views, bar, theme, naming rules, as you choose. The page is not executed: only its data is read. Under Edge / Chrome, Ctrl+S can then rewrite the same file, now in the new version.

First time? On the home screen, 🚀 Getting started shows where to open your file, then resumes once the model is loaded to show where to find the help and tutorials. ❓ Help ▾ › 🎓 Guided tour presents each area of the interface step by step (more complete with a loaded model). In each view, ❓ Help ▾ › 🎯 Tour of this view presents its menus and what they do.

Only the semantic .capella file is read. .aird (diagrams) and .afm files are refused: they do not contain the model elements.

Saving and sharing

⚠ When a model is loaded, the browser asks for confirmation before leaving the page (← Back button, closing the tab): otherwise the work in progress would be lost. Remember to 💾 Save.

💾 Save (Ctrl+S) writes the page directly to a file chosen once, then overwrites it at each save, without going through downloads (Edge / Chrome; elsewhere, the page is downloaded). Shift+click or Ctrl+Shift+S: save as. 💾 HTML page downloads the page. In both cases, the whole application is saved with the embedded model. When this file is opened, the model reloads by itself: handy to freeze a state or share an analysis with someone who does not have Capella.

The saved page contains: the model and its diagrams (.aird), the 🏠 home (project sheet, checklists, review plans, whiteboards, review packages and their feedback), the 💬 Review comments, the view bar (menus, pins), the dashboards, the ▤ Table tabs and columns (path columns, filters, widths, sort), the theme and the naming rules. Not kept: the version loaded for ⚖ Comparison and the filters of the other views.

📁 File › ⚙ Save the interface and views: the same settings without the model, in a .json file (parts of your choice); ⚙ Load an interface and views applies them again, for example with another model or a new version of the page.

Offline operation

The application works without a connection: all resources are embedded in the file, including the D3.js v7.9.0 graphics library (ISC licence). Exports (PDF, ZIP, PNG, SVG, CSV, HTML) are generated in the browser, without any external library, and the HTML reports produced are standalone too. A saved 💾 HTML page remains usable offline.

Showing a chain in the graph

Reading the graph

Hovering a node: its direct neighbours stay highlighted, the rest fades. Each node's banner carries the readable name of its type. The Element types panel only lists the types present in the tree, sorted by ARCADIA layer, with their number of elements.

✨ Path column (metachain)

Adds a computed column which, for each element of the table, follows a path of relations in the model and shows what it finds at the end. Examples: the functions allocated to each component, the components connected to a component through its ports, the name of the package owning a requirement.

Building the path: choose the start type (only its rows will be filled), then, at each step, the relation to follow; the type of the next step is deduced automatically. The last step can read a value (Name, ID, attribute); otherwise, the cell shows the names of the reached elements. The choices offered depend on the loaded model:

Name · ID · Type · Human Type · attributesDisplayed value (end of the path).
Owner [Type]First owning element of the chosen type.
Owned element [Type]Directly contained elements of the chosen type (e.g. a component's ports).
Capella relationsAllocation, realization, involvement… in both directions.
attribute → TypeElement designated by an attribute (source, target, involved…).
← incoming referenceElements designating this one (reverse direction).
via [Type] → [Type]Going through an intermediate element (e.g. port → Physical Link → opposite port).

👁 Live preview: choose a sample element of the start type (🔍 filter, list, Next ▸ to go to the next element whose cell would be filled). The preview shows the elements reached at each step, the step where the path stops if it finds nothing, the final content of the cell and the number of elements for which it will be filled.

+ Add a step · ✕ deletes a step and the following ones · ✏ (⊞ Columns menu) edits an existing column · the preview updates at each change.

Detail panel

Elements are preceded by their Capella icon (variant depending on actor, human, nature, function kind…, drawn by the Arcature viewer): details panel, cards, trees (Explorer and Relation Map), types, review.

A click on a name (almost everywhere) opens the detail panel: Human Type and type description, element description formatted as in Capella (‹/› HTML button: its original code; links to other elements are clickable), 💬 review buttons, attributes, outgoing references, incoming references (what points to this element?), owner and owned elements. Everything is clickable to navigate step by step.

⚡ Chains

📡 Flows & interfaces menu (📌 in ☰ for a direct button). ℹ Info (Relation Map view bar, or unfolded card) shows the chain information in the detail panel: type, layer, number of functions (components) and exchanges, inputs, outputs, owners, capabilities involving it, description; 🔎 opens the full detail of the element.

FunctionalChain, OperationalProcess and PhysicalPath are rebuilt as a graph: several inputs, several outputs, branches and loops are kept.

Filters and sub-views

Filter by type and by layer (OA, SA, LA, PA, EPBS), and by content: All / Non-empty / Empty (empty chain = no function or exchange involved). ▦ Diagrams: one card per chain. 🗺 Relation Map view: interactive graph (LR / TB / RL / radial / zigzag layouts, ⬡ Compact, ✂ Names) and injection into the main Relation Map.

Content of a card

  • Top-down diagram, Capella style: blue carried by an actor, green carried by the system, grey unallocated; operational processes (OA) in Capella colours: yellow activities, brown arrows; thick border = input or output.
  • Involved functions: flow order, type, allocation component, input/output role, number of incoming/outgoing exchanges.
  • Involved Functional Exchanges: numbered source → target, Exchange Items, carrying Component Exchange. For a physical path: components, Physical Links and allocated CEs.
  • Buttons 🖼 PNG · 📐 SVG · 📋 Copy (paste into Word/PowerPoint) · ⬇ CSV.

💬 Review comments

💬 Comment (open card, Relation Map view bar, ℹ Info) or right-click the header of a card: comment on the chain. Right-click a function of the diagram or graph: the comment is linked to the function and to the chain (“💬 Comment on the chain only” otherwise). In the comment window, the chain's functions are offered in one click (⚡ Link to functions). A commented chain shows 💬 in its header.

Right model?

Each comment and each export records the Capella project identifier (root Project element of the .capella: unique identifier created with the project, kept from one version to the next). On import, the review is compared with the loaded model: same project identifier → direct import; otherwise, share of the commented elements found in the model (identifiers that are also unique and stable). With fewer than 5 commented elements, this share is not enough: the import is direct only if all are found, otherwise a window compares both sides (file, project, elements found) and offers Import anyway or Cancel. A copied project keeps its element identifiers: it is recognised as a copy. 🧪 Use case — reviewing a Capella model

  1. Load the .capella file (drag and drop). Look at 🧭 Explorer › 📖 Type index to see what the model is made of.
  2. Browse with 🧭 Explorer (▦ Cards and 🌳 Tree); open the detail panel to follow incoming and outgoing references.
  3. Analyse a neighbourhood in 🗺 Relation Map: choose a component in the tree, set depth, layout and criteria.
  4. Review the chains in ⚡ Chains: inputs/outputs, unallocated functions (grey), exchanges without carrying CE.
  5. Check the interfaces: 🧱 System / Logical Component (Capella-style blocks with ports, orphan or unoriented ports), 🔀 Behavior Exchange (PA), ƒ⇆ Functional Exchange (functions as Capella-style blocks with pins, orphan ports, exchanges without Exchange Item), 🔌 Physical Link (links without CE), 🧩 Ports (FE ↔ CE ↔ PL alignment).
  6. Measure maturity in 🔬 Analyses: traceability coverage between layers, uncovered capabilities, incomplete state machines; compare with the previous version of the model (⚖ 📰 Release notes or 🔍 Review report, to copy into Word or Outlook) to prepare a review.
  7. Produce a deliverable: PDF of the chains with appendices, CSV of the checks and tables, HTML reports; or 💾 HTML page to share the whole analysis.
