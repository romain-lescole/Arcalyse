📖 Aide — Relation Map · Capella

Arcalyse — votre modèle, sous toutes ses coutures

Application autonome (un seul fichier HTML) pour explorer, analyser, contrôler et exporter un modèle Capella / ARCADIA sans ouvrir Capella — ou un modèle SysML v2, UML ou SysML v1. Le fichier est lu localement dans le navigateur : rien n'est envoyé.

Ouvrir un modèle

  1. Glissez-déposez votre fichier modèle — Capella (.capella, .melodymodeller, .xml) SysML v2 (.sysml, .kpar) UML / SysML v1 (.uml, .xmi, .mdzip, .qea, dossier d'un projet Rhapsody .rpy) ou exigences ReqIF (.reqifz, .reqif) — n'importe où dans la fenêtre : le format est reconnu. L'écran d'ouverture montre aussi une carte par format (Capella, SysML v2, UML / SysML v1) : quoi ouvrir (pour UML / SysML v1, selon l'outil : .mdzip de Cameo, .qea d'Enterprise Architect 16+, .uml + .notation de Papyrus, export .xmi), ce que vous obtiendrez et ce qui est sans objet ; ses boutons ouvrent le dossier du projet ou un sélecteur filtré sur ce format (plusieurs fichiers pour les .sysml d'un projet ou un .uml et son .notation). 📁 Dossier du projet… (ou 📁 Fichier › 📁 Ouvrir le dossier du projet…, ou un dossier déposé, sous Edge / Chrome) charge le projet en une fois : le .capella avec ses diagrammes .aird et ses bibliothèques, les .sysml d'un projet SysML v2, ou un modèle UML / SysML v1 (.uml avec son .notation, .xmi, .mdzip, .qea) ; s'il contient plusieurs modèles, vous choisissez lequel. Sous les cartes, 💡 Bon à savoir fait défiler des astuces sur les pièges courants (export .xmi de Cameo sans diagrammes, .notation seul, anciens projets d'EA…) : ‹ ›, les points et ⏸ pour les parcourir ; le défilement s'arrête au survol. Les commandes propres à Capella (🔄 mise à jour, 🔄 suivi du fichier) le disent dans leur libellé.
  2. Le modèle est analysé puis la vue 🏠 Accueil du projet s'ouvre automatiquement (informations, check-lists, plans de revue, dossiers de relecture).
  3. Nouvelle barre (3.0) : les vues sont rangées par intention — boutons directs 🏠 Accueil, 🔲 Diagrammes, ▤ Tableau, ▦ Matrice, puis les menus 🏗 Architecture, ✅ Vérifier et 💬 Revue & documents — et le champ 🔍 (Ctrl+K) trouve une vue, un élément ou un diagramme. Essentiel (par défaut) montre les vues les plus utilisées ; Complet ajoute les vues avancées.
  4. Pour changer de modèle, redéposez simplement un autre fichier (il remplace le modèle affiché).
  5. Pour une nouvelle version du même modèle : 📁 Fichier › 🔄 Charger une mise à jour du modèle montre d'abord le delta, puis met à jour après validation (voir 🔄 Suivi).
  6. Nouvelle version d'Arcalyse : 📄 Ouvrir une page de projet… (bandeau « Projet de travail ») sur l'écran d'accueil (ou 📁 Fichier › 📄 Ouvrir un projet de travail, ou la page déposée sur la fenêtre) reprend une page enregistrée avec une version précédente (à partir de la 2.1) : modèle, diagrammes, revue, accueil, tableaux de bord, ▤ Tableau, vues, barre, thème, règles de nommage, au choix. La page n'est pas exécutée : seules ses données sont lues. Sous Edge / Chrome, Ctrl+S peut ensuite réécrire le même fichier, désormais dans la nouvelle version.

Première utilisation ? Sur l'écran d'accueil, 🚀 Bien démarrer montre où ouvrir votre fichier, puis reprend une fois le modèle chargé pour montrer où trouver l'aide et les tutoriels. ❓ Aide ▾ › 🎓 Visite guidée présente chaque zone de l'interface pas à pas (plus complète avec un modèle chargé). Dans chaque vue, ❓ Aide ▾ › 🎯 Visite de cette vue en présente les menus et ce qu'ils font.

Pour Capella, les éléments du modèle sont dans le fichier sémantique .capella : un .aird (diagrammes) ne s'ouvre qu'en complément d'un modèle Capella (déposé avec lui, ou une fois le modèle chargé), et un .afm est refusé. De même, un .notation de Papyrus ne s'ouvre qu'avec son .uml.

Les grands ensembles

🗺 Relation MapGraphe interactif centré sur un élément et ses voisins, filtrable par types et relations.
▤ TableauTous les éléments du modèle en tableau : onglets de vues, colonnes d'attributs, de relations et par chemin, tri, filtres, export CSV.
▦ MatriceÉléments en lignes et en colonnes reliés par les relations choisies (allocations, échanges, exigences, liaisons SysML / UML, relations par chemin), comme la Dependency Matrix de Catia Magic.

Sauvegarder et partager

⚠ Quand un modèle est chargé, le navigateur demande une confirmation avant de quitter la page (bouton ← Précédent, fermeture de l'onglet) : sinon le travail en cours serait perdu. Pensez à 💾 Enregistrer.

💾 Enregistrer (Ctrl+S) écrit la page directement dans un fichier choisi une fois, puis l'écrase à chaque enregistrement, sans passer par les téléchargements (Edge / Chrome ; ailleurs, la page est téléchargée). Maj+clic ou Ctrl+Maj+S : enregistrer sous. 💾 Page HTML télécharge la page. Dans les deux cas, toute l'application est enregistrée avec le modèle embarqué. À l'ouverture de ce fichier, le modèle se recharge tout seul : pratique pour figer un état ou partager une analyse avec quelqu'un qui n'a pas Capella.

La page enregistrée contient : le modèle et ses diagrammes (.aird), l'🏠 accueil (fiche projet, check-lists, plans de revue, dossiers de relecture et leurs retours), les commentaires de 💬 Revue, la barre des vues (menus, épingles), les tableaux de bord, les onglets et colonnes du ▤ Tableau (colonnes par chemin, filtres, largeurs, tri), le thème et les règles de nommage. Ne sont pas conservés : la version chargée pour ⚖ Comparaison et les filtres des autres vues.

📁 Fichier › ⚙ Enregistrer l'interface et les vues : les mêmes réglages sans le modèle, dans un fichier .json (parties au choix) ; ⚙ Charger une interface et des vues les réapplique, par exemple avec un autre modèle ou une nouvelle version de la page.

Fonctionnement hors ligne

L'application fonctionne sans connexion : toutes les ressources sont intégrées au fichier, y compris la bibliothèque graphique D3.js v7.9.0 (licence ISC) et les composants d'Arcature, le projet frère : la visionneuse de diagrammes Capella (Apache 2.0, sauf trois modules adaptés d'Eclipse Capella et d'Eclipse Sirius, sous EPL-2.0), le lecteur SysML v2, le lecteur UML / SysML v1 et le lecteur ReqIF (Apache 2.0) — détails dans ℹ À propos. Ces composants font environ la moitié du fichier. Les exports (PDF, ZIP, PNG, SVG, CSV, HTML) sont générés dans le navigateur, sans bibliothèque externe, et les rapports HTML produits sont eux aussi autonomes. Une 💾 Page HTML sauvegardée reste utilisable hors ligne.

🗺 Relation Map

Graphe centré sur un élément de contexte : ses voisins sont affichés jusqu'à la profondeur choisie, selon les relations Capella sélectionnées (allocation fonction → composant, échanges, liens physiques, chaînes…).

En bas de la fenêtre, la barre d'état rappelle l'élément de contexte, le nombre de nœuds et d'éléments uniques affichés et la profondeur ; elle n'apparaît qu'en Relation Map. 🎯 Visite de cette vue choisit un élément de contexte s'il n'y en a pas encore, pour montrer un graphe.

🗂 Vues (onglets)

Sous la 2e barre, une barre d'onglets Vue 1 · Vue 2 · ＋, comme dans ▤ Tableau. Chaque vue retient l'élément de contexte, la profondeur, la disposition, les types et relations cochés (⚙ Filtres), les options d'affichage (# Nums, ⌁ Relations, ✂ Noms, ⊙ Unique, ⬡ Compact, légende), les éléments masqués, les nœuds repliés à la main, le zoom et la chaîne affichée. Panneau gauche

ArborescenceÉléments du modèle ayant au moins une relation, à leur place hiérarchique (chaînes comprises). Filtre texte avec surbrillance. Clic = recentre le graphe. Sélection multiple (Ctrl/Maj), propre à chaque vue. Au chargement, les couches (Operational Analysis, System Analysis…) sont dépliées. Occupe toute la hauteur libre du panneau. Lecture seule : la Relation Map ne modifie pas le modèle — ni dans l'arborescence et 🔎 Détail (renommage, ajout, suppression, déplacement, collage de liste), ni par le clic droit sur le graphe, ni dans les critères (nouveau, modifier ou supprimer un type ou un critère de relation). Les couleurs et les cases à cocher restent réglables. Arcalyse est un outil de lecture et d'analyse.

Afficher une chaîne dans le graphe

Clic sur une chaîne (⚡) dans l'arborescence, ou bouton 🗺 de la vue ⚡ Chaînes : la Relation Map passe en vue chaîne, qui affiche le graphe complet — plusieurs entrées, plusieurs sorties, ramifications et boucles — disposé en couches selon la disposition choisie (→ LR, ↓ TB, ← RL). Liseré bleu = porté par un acteur, vert = par le système, gris = non alloué ; badge ENTRÉE / SORTIE ; arêtes étiquetées par l'échange. Un bandeau résume la chaîne ; ✕ Quitter la chaîne, un double-clic sur un nœud ou un clic dans l'arborescence reviennent à la Relation Map.

Lecture du graphe

Survol d'un nœud : ses voisins directs restent en évidence, le reste s'estompe. Le bandeau de chaque nœud porte le nom lisible de son type. Le panneau Types d'éléments ne liste que les types présents dans l'arborescence, triés par couche ARCADIA, avec leur nombre d'éléments.

▤ Tableau

Tableau de tous les éléments du modèle, un par ligne, ouvert par le bouton ▤ Tableau de la barre. Onglets de vues

Chaque onglet garde sa propre vue : types d'éléments cochés, 🎯 portée (indépendants des autres vues et des autres onglets), colonnes affichées et leur ordre, filtres, largeurs et tri. Un nouvel onglet n'a aucun type coché : cochez ceux à lister dans la barre latérale. + ajoute un onglet (copie des colonnes de la vue affichée, sans type coché), double-clic le renomme, ✕ le ferme. Les onglets sont enregistrés avec la 💾 Page HTML et dans le fichier ⚙ de l'interface.

Colonnes, tri, filtres

🎯 PortéeCritère facultatif de l'onglet : les lignes sont limitées aux éléments contenus dans des éléments choisis (paquetage, couche, composant, fonction…). La fenêtre montre les éléments choisis (✕ pour retirer), le mode — contenu à tous les niveaux ou directement contenu seulement —, l'arbre du modèle (▶ déplier, case pour ajouter) et une recherche par nom ou type. Affichage 🌳 Arbre : avec une recherche, les résultats apparaissent dans leurs conteneurs, grisés quand ils ne correspondent pas eux-mêmes (cochables aussi). Affichage ☰ Liste : liste à plat triée par nom, avec le chemin des conteneurs, limitée à 300 lignes (précisez la recherche au-delà). Sans élément choisi : tout le modèle. Les lignes d'un onglet = types cochés ∩ portée, puis filtres de colonnes ; le compteur rappelle la portée.
☰ Lignes · 🌳 ArbreAffichage de l'onglet. 🌳 Arbre : les lignes sont rangées sous leurs conteneurs (avec une 🎯 portée, à partir des éléments de portée) ; ▶ / ▼ dans la première colonne. Le menu ▾ à côté de 🌳 Arbre regroupe les options : Compact (par défaut : chaque ligne directement sous son plus proche ancêtre qui est lui-même une ligne, ex. composants et sous-composants, sans les paquetages) ou Conteneurs grisés (paquetages et conteneurs intermédiaires affichés, grisés et sans valeurs) ; ⊞ Tout déplier, ⊟ Tout réduire, Niveau 1 · 2 · 3 (les conteneurs ne comptent pas). L'ordre des éléments de même niveau suit le tri ; ⬇ CSV ajoute les colonnes Niveau et Chemin.

Ctrl+C ou 📋 Copier : à coller dans Excel ou Word ; une cellule à plusieurs éléments reste une seule cellule, avec un élément par ligne (quel que soit ≡ En ligne / ☰ Empilé). Échap ou un clic hors du tableau efface la sélection.

✨ Colonne par chemin (metachain)

Ajoute une colonne calculée qui, pour chaque élément du tableau, suit un chemin de relations dans le modèle et affiche ce qu'elle trouve au bout. Exemples : les fonctions allouées à chaque composant, les composants reliés à un composant par ses ports, le nom du paquetage propriétaire d'une exigence.

Construire le chemin : choisir le type de départ (seules ses lignes seront remplies), puis, à chaque étape, la relation à suivre ; le type de l'étape suivante est déduit automatiquement. La dernière étape peut lire une valeur (Name, ID, attribut) ; sinon, la cellule affiche le nom des éléments atteints. Les choix proposés dépendent du modèle chargé :

Name · ID · Type · Human Type · attributsValeur affichée (fin du chemin).
Owner [Type]Premier élément propriétaire du type choisi.
Owned element [Type]Éléments contenus directement, du type choisi (ex. les ports d'un composant).
Relations CapellaAllocation, réalisation, implication… dans les deux sens.
Liaisons SysML / UMLModèle SysML v2 ou UML / SysML v1 : typage, composition, satisfy, allocation… du lecteur d'Arcature, dans les deux sens.
attribut → TypeÉlément désigné par un attribut (source, target, involved…).

via [Type] → [Type]Passage par un élément intermédiaire (ex. port → Physical Link → port opposé).

👁 Aperçu en direct : choisissez un élément d'exemple du type de départ (filtre 🔍, liste, Suivant ▸ pour passer au prochain élément dont la cellule serait remplie). L'aperçu montre les éléments atteints à chaque étape, l'étape où le chemin s'arrête s'il ne trouve rien, le contenu final de la cellule et le nombre d'éléments pour lesquels elle sera remplie.

📘 Rapports automatiques (bouton 📘 Rapports de la barre, à côté de 📐 Tableau de bord, ou cadre en haut de la liste des dossiers) : crée un dossier selon un plan type d'ingénierie système, rempli à partir du modèle, puis entièrement modifiable et exportable comme tout dossier (page HTML à commenter, Word). 📘 Spécification technique du système (boîte noire), deux plans : plan 1 : objet, domaine d'application (contexte, système, diagrammes de missions et capacités), documents, terminologie, analyse fonctionnelle (missions, capacités, chaînes), exigences fonctionnelles par fonction système (description, entrées et sorties externes, diagrammes), interfaces externes (échanges avec les acteurs, environnement, entrées, sorties), exigences opérationnelles (scénarios, modes), sûreté de fonctionnement, contraintes, vérification ; plan 2 : introduction (objet, documents, terminologie), présentation du système (finalité, mission et objectifs ; contexte physique / organique et fonctionnel ; parties prenantes), exigences techniques (fonctionnelles par fonction système, performance, interfaces fonctionnelles et physiques, opérationnelles et scénarios, contraintes, validation et certification). 📗 Dossier de conception du système (boîte blanche) : architecture logique (composants, flux externes et internes, éléments échangés), chaînes fonctionnelles LA (diagrammes et ⇶ liens entre couches), séquences, architecture physique (composants, interfaces physiques externes et internes, allocation LA → PA), flux physiques, constituants et exigences dérivées par constituant (fonctions allouées, y compris déployées, liens physiques). Les parties que le modèle ne renseigne pas sont des textes « [À rédiger — …] » ; les diagrammes sont choisis par couche et par type (ouvrez le .aird avant). 📘 SSS — Spécification du système / sous-système et 📗 SSDD — Description de la conception du système / sous-système : plans MIL-STD-498 (DID DI-IPSC-81431 et DI-IPSC-81432), numérotation du DID gardée. Une fenêtre demande le périmètre : le système (System de la SA) ou un sous-système (composant SA, LA ou PA cherché par son nom) ; l'intérieur du périmètre (sous-composants, composants déployés), ses fonctions, ses échanges avec l'extérieur et ses partenaires en sont déduits. SSS : états et modes, une section par capacité (sinon par fonction), une interface externe par partenaire (échanges de composants et fonctionnels), interfaces internes, données, ressources informatiques (PA : nœuds, comportements, liens physiques), contraintes, et des sections d'exigences repérées par mots-clés (sûreté, sécurité, environnement, qualité, personnel, formation, logistique, emballage…). SSDD : décisions de conception, composants (sous-composants, fonctions allouées, réalisations, déploiement), concept d'exécution (chaînes, scénarios, modes), une section par interface (éléments échangés, échanges fonctionnels alloués, liens physiques porteurs). Les tableaux d'exigences montrent identifiant, texte, priorité et vérification (attribut d'exigence ou propriété PVMT dont le nom contient « priorit » ou « vérif / qualif / méthode »), éléments liés. Ce que le modèle ne contient pas est une invite « [À compléter — …] » qui rappelle ce que le DID attend.

La liste de gauche et la palette 📎 se règlent en largeur en glissant leur bord (double-clic : largeur par défaut) ; la largeur est enregistrée dans la page et vaut pour tous les onglets. 🧭 Plan (sous la liste des dossiers) : volet de navigation du dossier ouvert, chapitres numérotés ; un clic va au chapitre (en le dépliant) ; ⊟ / ⊞ replient ou déplient tous les chapitres. Plier ou déplier un chapitre ne ramène plus en haut du document. La page HTML exportée affiche aussi son sommaire dans un volet à gauche sur les grands écrans.

👁 Aperçu (en-tête du dossier ou du modèle) : rendu du rapport tel que l'exporte la page HTML, affiché par-dessus l'application sans rien télécharger ; bascule 📄 Lecture / 💬 Avec commentaires, 🖨 Imprimer, ⬇ Page HTML, ⧉ pour l'ouvrir dans une fenêtre séparée (par exemple sur un autre écran : un nouveau clic sur 👁 Aperçu l'y actualise), ✕ ou Échap pour fermer. Pour un 🧩 modèle, l'aperçu montre le rapport qu'il produirait sur le modèle chargé, sans le créer.

💬 Commentaires dans la page HTML (en-tête du dossier) : décoché, la page HTML exportée est un simple rapport à lire et imprimer (sans 💬, ni nom de relecteur, ni enregistrement). Décoché par défaut pour les rapports automatiques. Le Word garde ses commentaires Word ; son sommaire est fait de liens vers les chapitres.

🧩 Mes modèles de rapport

Pour créer son propre rapport automatique : ✚ Nouveau modèle (cadre 📘 Rapports automatiques) crée un modèle prérempli d'un exemple à adapter. Un modèle s'édite comme un dossier (chapitres, textes, diagrammes et éléments glissés), avec deux sortes de blocs en plus :

🔁 Boucle « pour chaque »Chapitre répété pour chaque élément trouvé : type (fonctions, composants, nœuds physiques, acteurs, chaînes, capacités, missions, échanges, liens physiques, éléments échangés, diagrammes), couche, filtre (alloués au système, à un acteur, feuilles, liés à l'élément de la boucle englobante pour des boucles imbriquées : fonctions d'un composant, fonctions d'une chaîne, échanges d'une fonction…), nom contient, nombre maximal. Titre du chapitre : {nom}, {type}, {couche} (aussi dans les textes). Case Description : description de l'élément sous le titre.
⚙ Contenu automatiqueCalculé pour l'élément de la boucle : description, diagrammes dont il est l'élément représenté, diagrammes par couche et type (SAB, LAB, ES…), échanges fonctionnels entrants / sortants (avec l'extérieur seulement ou tous), fonctions allouées (et déployées), liens physiques, chaînes qui impliquent la fonction, tableau d'éléments (type, couche, filtre), 🔗 liens entre couches.

🧩 Modèles sur mesure (SysML v1 / v2, aussi Capella)

Sur un modèle SysML, les méthodes sont libres : les boucles et les contenus ne supposent ni couches ni ARCADIA. Type ✨ Au choix (type, portée, relation, chemin) d'une boucle ou d'un tableau d'éléments :

TypeFamille usuelle (blocs, parts, ports, interfaces, connecteurs, fonctions — activités, actions ou éléments stéréotypés « fonction » —, pins et paramètres, machines à états, interactions, cas d'utilisation, acteurs, exigences, cas de test, contraintes, objets échangés, valeurs, paquetages), type exact ou stéréotype du modèle (avec leur nombre).
PortéeTout le modèle ; dans un paquetage ou un bloc choisi (📍, directement ou à tous les niveaux) ; contenus dans l'élément englobant ; à son intérieur (contenus, parts et leurs types, de proche en proche) ; reliés à lui par une relation (liaisons du lecteur : allocate, satisfy, verify, perform, composition, typage…, ou relations Capella ; sens au choix, depuis l'élément ou tout son intérieur) ; atteints par un ✨ chemin (même moteur que la colonne par chemin du ▤ Tableau, avec aperçu). « Élément englobant » : élément de la boucle englobante, sinon le 🎯 sujet du modèle. Case et son type : chercher aussi depuis ce qui type l'élément (le bloc d'une part, la part def d'une part SysML v2). Filtres : nom contient, texte contient (expression, « | » = ou), ordre du modèle ou par nom ; « si aucun : rien » pour ne pas écrire de phrase quand la boucle ne trouve rien.
ContenusPropriétés et valeurs (stéréotypes et leurs propriétés, déclaration, multiplicité, valeurs des attributs), liens (relation au choix, sens), ports, pins et paramètres (entrées, sorties ou les deux, avec leur sens, leur type et ce à quoi ils sont reliés), connexions (touchant l'élément ou ses ports, ou internes : de, vers, objets transportés par les ItemFlow), ✨ information par chemin (valeur ou liste d'éléments), diagrammes dont il est l'élément représenté (filtre par genre : ibd, AD, STV…). Les tableaux vides sont omis, sauf « même vide ».
ColonnesUn tableau d'éléments « au choix » reçoit des colonnes : type, description, propriétaire, typé par, stéréotypes, identifiant, texte (exigence, contrainte), sens, attribut (ex. Requirement.text), relation (ex. satisfaite par, vérifiée par), ✨ chemin.
🎯 SujetEn tête du modèle : système ou sous-système décrit, élément englobant des boucles de premier niveau, {sujet} dans les titres et textes. Le même modèle sert pour un sous-système : changer seulement le sujet.

Exemple : boucle « pour chaque part contenue dans l'élément englobant », puis dedans un sous-chapitre « Fonctions allouées » avec une boucle « pour chaque fonction reliée par allocate / perform », et, dans celle-ci, un sous-chapitre Entrées (ports, pins et paramètres : entrées), un sous-chapitre Sorties et les diagrammes de la fonction.

  2. Vérifier le 🎯 sujet en tête du modèle (le système proposé) ; pour un sous-système, 📍 Choisir… un autre bloc ou une autre part.
  3. Dans Composants du système, lire les boucles : « pour chaque part contenue dans l'élément englobant », puis « pour chaque fonction reliée par allocate / perform », avec Entrées et Sorties (ports, pins et paramètres) et les diagrammes de la fonction. Adapter le type (ex. votre stéréotype « Function »), la portée, la relation ou un ✨ chemin.
  4. Ajouter ce qui manque : ⚙ Contenu automatique (propriétés, liens, connexions, information par chemin) ou ＋ Colonne dans un tableau « au choix ».
  5. ▶ Générer le rapport, puis 👁 Aperçu, 📤 Page HTML à commenter ou 📝 Word. À la version suivante du modèle, ▶ le régénère ; 💾 .json le partage.

🧪 Cas d'usage — revue d'un modèle Capella

  1. Charger le .capella (glisser-déposer). Consulter 🏠 Accueil › 🧩 Contenu du modèle pour voir la composition du modèle.
  2. Parcourir avec 🧭 Explorateur (🃏 Cartes et 🌳 Arborescence) ; ouvrir le panneau de détail pour suivre les références entrantes et sortantes.
  3. Analyser un voisinage dans 🗺 Relation Map : choisir un composant dans l'arborescence, régler profondeur, disposition et critères.
  4. Revoir les chaînes dans ⚡ Chaînes : entrées/sorties, fonctions non allouées (gris), échanges sans CE porteur.
  5. Contrôler les interfaces : 🧱 System / Logical Component (blocs à ports façon Capella, ports orphelins ou non orientés), 🔀 Behavior Exchange (PA), ƒ⇆ Functional Exchange (fonctions en blocs à pins façon Capella, ports orphelins, échanges sans Exchange Item), 🔌 Physical Link (liens sans CE), 🧩 Ports (alignement FE ↔ CE ↔ PL).
  6. Mesurer la maturité dans 🔬 Analyses : couverture de traçabilité entre couches, capacités non couvertes, machines à états incomplètes ; comparer avec la version précédente du modèle (⚖ rapport 📰 Notes de version ou 🔍 Revue, à copier dans Word ou Outlook) pour préparer une revue.
  7. Produire un livrable : PDF des chaînes avec annexes, CSV des contrôles et des tables, rapports HTML ; ou 💾 Page HTML pour partager toute l'analyse.
