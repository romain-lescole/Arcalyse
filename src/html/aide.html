📖 Aide — Relation Map · Capella

Arcalyse — votre modèle Capella, sous toutes ses coutures

Application autonome (un seul fichier HTML) pour explorer, analyser, contrôler et exporter un modèle Capella / ARCADIA sans ouvrir Capella. Le fichier .capella est lu localement dans le navigateur.

Ouvrir un modèle

  1. Glissez-déposez un fichier .capella n'importe où dans la fenêtre, ou cliquez 📂 Fichier .capella… sur l'écran d'accueil (ou 📁 Fichier › 🔷 Ouvrir un modèle Capella). 📁 Dossier du projet… (ou 📁 Fichier › 📁 Ouvrir le dossier du projet…, ou un dossier déposé, sous Edge / Chrome) charge ensemble le .capella et ses diagrammes .aird ; s'il contient plusieurs modèles, vous choisissez lequel.
  2. Le modèle est analysé puis la vue 🏠 Accueil du projet s'ouvre automatiquement (informations, check-lists, plans de revue, tableaux blancs, dossiers de relecture).
  3. ⚡ Chaînes n'est plus épinglé par défaut : il est dans le menu 📡 Flux & interfaces (📌 dans ☰ pour l'épingler de nouveau).
  4. Pour changer de modèle, redéposez simplement un autre fichier (il remplace le modèle affiché).
  5. Pour une nouvelle version du même modèle : 📁 Fichier › 🔄 Charger une mise à jour du modèle montre d'abord le delta, puis met à jour après validation (voir 🔄 Suivi).
  6. Nouvelle version d'Arcalyse : 📄 Projet de travail (.html)… sur l'écran d'accueil (ou 📁 Fichier › 📄 Ouvrir un projet de travail, ou la page déposée sur la fenêtre) reprend une page enregistrée avec une version précédente (à partir de la 2.1) : modèle, diagrammes, revue, accueil, tableaux de bord, ▤ Tableau, vues, barre, thème, règles de nommage, au choix. La page n'est pas exécutée : seules ses données sont lues. Sous Edge / Chrome, Ctrl+S peut ensuite réécrire le même fichier, désormais dans la nouvelle version.

Première utilisation ? Sur l'écran d'accueil, 🚀 Bien démarrer montre où ouvrir votre fichier, puis reprend une fois le modèle chargé pour montrer où trouver l'aide et les tutoriels. ❓ Aide ▾ › 🎓 Visite guidée présente chaque zone de l'interface pas à pas (plus complète avec un modèle chargé). Dans chaque vue, ❓ Aide ▾ › 🎯 Visite de cette vue en présente les menus et ce qu'ils font.

Seul le fichier sémantique .capella est lu. Les fichiers .aird (diagrammes) et .afm sont refusés : ils ne contiennent pas les éléments du modèle.

Sauvegarder et partager

⚠ Quand un modèle est chargé, le navigateur demande une confirmation avant de quitter la page (bouton ← Précédent, fermeture de l'onglet) : sinon le travail en cours serait perdu. Pensez à 💾 Enregistrer.

💾 Enregistrer (Ctrl+S) écrit la page directement dans un fichier choisi une fois, puis l'écrase à chaque enregistrement, sans passer par les téléchargements (Edge / Chrome ; ailleurs, la page est téléchargée). Maj+clic ou Ctrl+Maj+S : enregistrer sous. 💾 Page HTML télécharge la page. Dans les deux cas, toute l'application est enregistrée avec le modèle embarqué. À l'ouverture de ce fichier, le modèle se recharge tout seul : pratique pour figer un état ou partager une analyse avec quelqu'un qui n'a pas Capella.

La page enregistrée contient : le modèle et ses diagrammes (.aird), l'🏠 accueil (fiche projet, check-lists, plans de revue, tableaux blancs, dossiers de relecture et leurs retours), les commentaires de 💬 Revue, la barre des vues (menus, épingles), les tableaux de bord, les onglets et colonnes du ▤ Tableau (colonnes par chemin, filtres, largeurs, tri), le thème et les règles de nommage. Ne sont pas conservés : la version chargée pour ⚖ Comparaison et les filtres des autres vues.

📁 Fichier › ⚙ Enregistrer l'interface et les vues : les mêmes réglages sans le modèle, dans un fichier .json (parties au choix) ; ⚙ Charger une interface et des vues les réapplique, par exemple avec un autre modèle ou une nouvelle version de la page.

Fonctionnement hors ligne

L'application fonctionne sans connexion : toutes les ressources sont intégrées au fichier, y compris la bibliothèque graphique D3.js v7.9.0 (licence ISC). Les exports (PDF, ZIP, PNG, SVG, CSV, HTML) sont générés dans le navigateur, sans bibliothèque externe, et les rapports HTML produits sont eux aussi autonomes. Une 💾 Page HTML sauvegardée reste utilisable hors ligne.

🗺 Relation Map

Graphe centré sur un élément de contexte : ses voisins sont affichés jusqu'à la profondeur choisie, selon les relations Capella sélectionnées (allocation fonction → composant, échanges, liens physiques, chaînes…).

En bas de la fenêtre, la barre d'état rappelle l'élément de contexte, le nombre de nœuds et d'éléments uniques affichés et la profondeur ; elle n'apparaît qu'en Relation Map. 🎯 Visite de cette vue choisit un élément de contexte s'il n'y en a pas encore, pour montrer un graphe.

🗂 Vues (onglets)

Sous la 2e barre, une barre d'onglets Vue 1 · Vue 2 · ＋, comme dans ▤ Tableau. Chaque vue retient l'élément de contexte, la profondeur, la disposition, les types et relations cochés (⚙ Filtres), les options d'affichage (# Nums, ⌁ Relations, ✂ Noms, ⊙ Unique, ⬡ Compact, légende), les éléments masqués, les nœuds repliés à la main, le zoom et la chaîne affichée. Tout changement est enregistré dans la vue active, sans bouton « Enregistrer » ; les couleurs restent communes à toutes les vues.

Panneau gauche

ArborescenceÉléments du modèle ayant au moins une relation, à leur place hiérarchique (chaînes comprises). Filtre texte avec surbrillance. Clic = recentre le graphe. Sélection multiple (Ctrl/Maj), propre à chaque vue. Au chargement, les couches (Operational Analysis, System Analysis…) sont dépliées. Occupe toute la hauteur libre du panneau. Lecture seule : la Relation Map ne modifie pas le modèle — ni dans l'arborescence et 🔎 Détail (renommage, ajout, suppression, déplacement, collage de liste), ni par le clic droit sur le graphe, ni dans les critères (nouveau, modifier ou supprimer un type ou un critère de relation). Les couleurs et les cases à cocher restent réglables. Arcalyse est un outil de lecture et d'analyse.

Afficher une chaîne dans le graphe

Clic sur une chaîne (⚡) dans l'arborescence, ou bouton 🗺 de la vue ⚡ Chaînes : la Relation Map passe en vue chaîne, qui affiche le graphe complet — plusieurs entrées, plusieurs sorties, ramifications et boucles — disposé en couches selon la disposition choisie (→ LR, ↓ TB, ← RL). Liseré bleu = porté par un acteur, vert = par le système, gris = non alloué ; badge ENTRÉE / SORTIE ; arêtes étiquetées par l'échange. Un bandeau résume la chaîne ; ✕ Quitter la chaîne, un double-clic sur un nœud ou un clic dans l'arborescence reviennent à la Relation Map.

Lecture du graphe

Survol d'un nœud : ses voisins directs restent en évidence, le reste s'estompe. Le bandeau de chaque nœud porte le nom lisible de son type. Le panneau Types d'éléments ne liste que les types présents dans l'arborescence, triés par couche ARCADIA, avec leur nombre d'éléments.

Couleurs ARCADIA

OA Analyse opérationnelle · SA Analyse système · LA Architecture logique · PA Architecture physique (PC NODE, PC BEHAVIOR) · EPBS Éléments de configuration.

▤ Tableau

Tableau de tous les éléments du modèle, un par ligne, ouvert par le bouton ▤ Tableau de la barre. Les lignes suivent les types cochés dans la barre latérale (couches dépliées) ; un double-clic sur une ligne ouvre le panneau de détail. Pas de recherche globale ni de filtre de couche ici : les champs Filtrer… de chaque colonne les remplacent.

Onglets de vues

Chaque onglet garde sa propre vue : types d'éléments cochés, 🎯 portée (indépendants des autres vues et des autres onglets), colonnes affichées et leur ordre, filtres, largeurs et tri. Un nouvel onglet n'a aucun type coché : cochez ceux à lister dans la barre latérale. + ajoute un onglet (copie des colonnes de la vue affichée, sans type coché), double-clic le renomme, ✕ le ferme. Les onglets sont enregistrés avec la 💾 Page HTML et dans le fichier ⚙ de l'interface.

✨ Colonne par chemin (metachain)

Ajoute une colonne calculée qui, pour chaque élément du tableau, suit un chemin de relations dans le modèle et affiche ce qu'elle trouve au bout. Exemples : les fonctions allouées à chaque composant, les composants reliés à un composant par ses ports, le nom du paquetage propriétaire d'une exigence.

Construire le chemin : choisir le type de départ (seules ses lignes seront remplies), puis, à chaque étape, la relation à suivre ; le type de l'étape suivante est déduit automatiquement. La dernière étape peut lire une valeur (Name, ID, attribut) ; sinon, la cellule affiche le nom des éléments atteints. Les choix proposés dépendent du modèle chargé :

Name · ID · Type · Human Type · attributsValeur affichée (fin du chemin).
Owner [Type]Premier élément propriétaire du type choisi.
Owned element [Type]Éléments contenus directement, du type choisi (ex. les ports d'un composant).
Relations CapellaAllocation, réalisation, implication… dans les deux sens.
attribut → TypeÉlément désigné par un attribut (source, target, involved…).
← référence entranteÉléments qui désignent celui-ci (sens inverse).
via [Type] → [Type]Passage par un élément intermédiaire (ex. port → Physical Link → port opposé).

👁 Aperçu en direct : choisissez un élément d'exemple du type de départ (filtre 🔍, liste, Suivant ▸ pour passer au prochain élément dont la cellule serait remplie). L'aperçu montre les éléments atteints à chaque étape, l'étape où le chemin s'arrête s'il ne trouve rien, le contenu final de la cellule et le nombre d'éléments pour lesquels elle sera remplie.

+ Ajouter une étape · ✕ supprime une étape et les suivantes · ✏ (menu ⊞ Colonnes) modifie une colonne existante · l'aperçu se met à jour à chaque changement.

🧪 Cas d'usage — revue d'un modèle Capella

  1. Charger le .capella (glisser-déposer). Consulter 🧭 Explorateur › 📖 Index des types pour voir la composition du modèle.
  2. Parcourir avec 🧭 Explorateur (▦ Cartes et 🌳 Arborescence) ; ouvrir le panneau de détail pour suivre les références entrantes et sortantes.
  3. Analyser un voisinage dans 🗺 Relation Map : choisir un composant dans l'arborescence, régler profondeur, disposition et critères.
  4. Revoir les chaînes dans ⚡ Chaînes : entrées/sorties, fonctions non allouées (gris), échanges sans CE porteur.
  5. Contrôler les interfaces : 🧱 System / Logical Component (blocs à ports façon Capella, ports orphelins ou non orientés), 🔀 Behavior Exchange (PA), ƒ⇆ Functional Exchange (fonctions en blocs à pins façon Capella, ports orphelins, échanges sans Exchange Item), 🔌 Physical Link (liens sans CE), 🧩 Ports (alignement FE ↔ CE ↔ PL).
  6. Mesurer la maturité dans 🔬 Analyses : couverture de traçabilité entre couches, capacités non couvertes, machines à états incomplètes ; comparer avec la version précédente du modèle (⚖ rapport 📰 Notes de version ou 🔍 Revue, à copier dans Word ou Outlook) pour préparer une revue.
  7. Produire un livrable : PDF des chaînes avec annexes, CSV des contrôles et des tables, rapports HTML ; ou 💾 Page HTML pour partager toute l'analyse.
