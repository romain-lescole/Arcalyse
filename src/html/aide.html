📖 Aide — Relation Map · Capella

Arcalyse — votre modèle Capella, sous toutes ses coutures

Application autonome (un seul fichier HTML) pour explorer, analyser, contrôler et exporter un modèle Capella / ARCADIA sans ouvrir Capella. Le fichier .capella est lu localement dans le navigateur : aucune donnée n'est envoyée.

Ouvrir un modèle

  1. Glissez-déposez un fichier .capella n'importe où dans la fenêtre, ou cliquez 📂 Parcourir… sur l'écran d'accueil (ou 📁 Fichier › 🔷 Ouvrir un modèle Capella).
  2. Le modèle est analysé puis la vue 🧭 Explorateur › ▦ Cartes s'ouvre automatiquement.
  3. Pour changer de modèle, redéposez simplement un autre fichier (il remplace le modèle affiché).
  4. Pour une nouvelle version du même modèle : 📁 Fichier › 🔄 Charger une mise à jour du modèle montre d'abord le delta, puis met à jour après validation (voir 🔄 Suivi).

Première utilisation ? Sur l'écran d'accueil, 🚀 Bien démarrer montre où ouvrir votre fichier, puis reprend une fois le modèle chargé pour montrer où trouver l'aide et les tutoriels. ? Aide ▾ › 🎓 Visite guidée présente chaque zone de l'interface pas à pas (plus complète avec un modèle chargé). Dans chaque vue, ? Aide ▾ › 🎯 Visite de cette vue en présente les menus et ce qu'ils font.

Seul le fichier sémantique .capella est lu. Les fichiers .aird (diagrammes) et .afm sont refusés : ils ne contiennent pas les éléments du modèle.

Les trois modes

🗺 Relation MapGraphe interactif centré sur un élément et ses voisins, filtrable par types et relations.
📊 Table ViewTableau de tous les éléments du fichier, avec colonnes calculées (Metachain).
🔷 Vues CapellaVues d'analyse dédiées : explorateur (arborescence, cartes, tableau, index), liens, chaînes, interfaces, ports, index.

Sauvegarder et partager

⚠ Quand un modèle est chargé, le navigateur demande une confirmation avant de quitter la page (bouton ← Précédent, fermeture de l'onglet) : sinon le travail en cours serait perdu. Pensez à 💾 Enregistrer.

💾 Enregistrer (Ctrl+S) écrit la page directement dans un fichier choisi une fois, puis l'écrase à chaque enregistrement, sans passer par les téléchargements (Edge / Chrome ; ailleurs, la page est téléchargée). Maj+clic ou Ctrl+Maj+S : enregistrer sous. 💾 Page HTML télécharge la page. Dans les deux cas, toute l'application est enregistrée avec le modèle embarqué. À l'ouverture de ce fichier, le modèle se recharge tout seul : pratique pour figer un état ou partager une analyse avec quelqu'un qui n'a pas Capella.

La page enregistrée contient : le modèle, la barre des vues (menus, épingles), les tableaux de bord, les colonnes et vues du 📋 Tableau et de la 📊 Table View (colonnes personnalisées, onglets, filtres, largeurs), le thème et les règles de nommage. Ne sont pas conservés : la version chargée pour ⚖ Comparaison et les filtres des autres vues.

📁 Fichier › ⚙ Enregistrer l'interface et les vues : les mêmes réglages sans le modèle, dans un fichier .json (parties au choix) ; ⚙ Charger une interface et des vues les réapplique, par exemple avec un autre modèle ou une nouvelle version de la page.

Sécurité et fonctionnement hors ligne

Aucune connexion réseau n'est nécessaire ni utilisée. Toutes les ressources sont intégrées au fichier, y compris la bibliothèque graphique D3.js v7.9.0 (licence ISC). Aucun cookie, aucun stockage navigateur, aucun traçage, aucun envoi de données. Les exports (PDF, ZIP, PNG, SVG, CSV, HTML) sont générés dans le navigateur, sans bibliothèque externe, et les rapports HTML produits sont eux aussi autonomes. Une 💾 Page HTML sauvegardée reste utilisable hors ligne.

Afficher une chaîne dans le graphe

Clic sur une chaîne (⚡) dans l'arborescence, ou bouton 🗺 de la vue ⚡ Chaînes : la Relation Map passe en vue chaîne, qui affiche le graphe complet — plusieurs entrées, plusieurs sorties, ramifications et boucles — disposé en couches selon la disposition choisie (→ LR, ↓ TB, ← RL). Liseré bleu = porté par un acteur, vert = par le système, gris = non alloué ; badge ENTRÉE / SORTIE ; arêtes étiquetées par l'échange. Un bandeau résume la chaîne ; ✕ Quitter la chaîne, un double-clic sur un nœud ou un clic dans l'arborescence reviennent à la Relation Map.

Lecture du graphe

Survol d'un nœud : ses voisins directs restent en évidence, le reste s'estompe. Le bandeau de chaque nœud porte le nom lisible de son type. Le panneau Types d'éléments ne liste que les types présents dans l'arborescence, triés par couche ARCADIA, avec leur nombre d'éléments.

⚡ Chaînes

Filtres et sous-vues

Filtre par type et par couche (OA, SA, LA, PA, EPBS), et par contenu : Toutes / Non vides / Vides (chaîne vide = aucune fonction ni échange impliqué). ▦ Diagrammes : une carte par chaîne. 🗺 Vue Relation Map : graphe interactif (dispositions LR / TB / RL / radiale / zigzag, ⬡ Compact, ✂ Noms) et injection dans la Relation Map principale.

Contenu d'une carte

  • Diagramme de haut en bas, style Capella : bleu porté par un acteur, vert porté par le système, gris non alloué ; processus opérationnels (OA) aux couleurs de Capella : activités jaunes, flèches brunes ; bordure épaisse = entrée ou sortie.
  • Fonctions impliquées : ordre du flux, type, composant d'allocation, rôle entrée/sortie, nombre d'échanges entrants/sortants.
  • Functional Exchanges impliqués : source → cible numérotées, Exchange Items, Component Exchange porteur. Pour un chemin physique : composants, Physical Links et CE alloués.
  • Boutons 🖼 PNG · 📐 SVG · 📋 Copier (coller dans Word/PowerPoint) · ⬇ CSV.

🔌 Interfaces & ports

Vues d'interfaces du menu 📡 Flux & interfaces, du fonctionnel au physique, dans l'ordre des onglets : ƒ⇆ Functional Exchange, 🟨 Operational Analysis, 🧱 System Component, 🧱 Logical Component, 🔀 Behavior Exchange, 🔌 Physical Link, 🎬 Scénarios, puis 🧩 Ports. Chacune s'ouvre en ◧ Vue Blocs (rendu façon Capella, navigation d'un bloc à l'autre) et propose aussi des vues Ligne / Composant (ou Fonction), une ▦ Matrice N² (clic sur une cellule = liste des échanges) et un rapport 🩺 Contrôles. Dans ƒ⇆, chaque bloc indique en petit, en haut, son rattachement : composant ou acteur d'allocation (clic : son bloc dans la vue de sa couche) ou, à défaut, sa fonction mère (clic : son bloc). En thème sombre, un conseil rappelle que la Vue Blocs est plus lisible, et plus proche de Capella, avec le thème Office 2007 ou Clair. Les barres de commandes restent visibles en haut quand on fait défiler la vue (de même dans ⚡ Chaînes, ƒ Fonctions et 🔬 Analyses). Comme dans ƒ Fonctions, les commandes de chaque barre sont entourées par catégorie (onglets, vues, filtres et champs, exports). Dans les tableaux de 🔬 Analyses et de ƒ Fonctions › ⛓ Traçabilité, les noms de colonnes et la ligne de filtres restent eux aussi visibles au défilement.

Exports HTML (🔀 et 🔌) : ⬇ HTML = la vue affichée ; ⬇ HTML (toutes les vues) = rapport à onglets Vue Ligne / Vue Composant / Matrice / Contrôles, filtres appliqués, avec recherche et matrice cliquable. Les fichiers sont autonomes et reprennent les couleurs du thème courant.

Répartition par couche : 🧱 System Component (SA) et 🧱 Logical Component (LA) pour les composants et leurs Component Exchanges ; 🔀 Behavior Exchange pour les Component Exchanges de la couche PA entre Physical Components Behavior ; 🔌 Physical Link pour les liens entre Physical Components Node.

ƒ⇆ Functional Exchange

Échanges entre fonctions (toutes couches), même organisation que 🧱 Logical Component, avec un filtre par couche (OA, SA, LA, PA) et un filtre Allocation comme dans ƒ Fonctions (🧩 Système, 👤 Acteurs, ∅ Non allouées ; double-clic : uniquement celle-ci) et la liste Tous les allocataires de la couche (acteurs, puis système et sous-systèmes en arbre, sous-composants compris ; en OA : entités et acteurs opérationnels) ; dans les vues d'échanges, un échange est gardé si l'une de ses deux fonctions correspond :

◧ Vue BlocsVue par défaut. Chaque fonction dessinée comme dans Capella : boîte arrondie au nom de la fonction, verte si allouée au système, bleue si allouée à un acteur, grise si non allouée (ou fonction mère) ; pins d'entrée (verts) à gauche et de sortie (orange) à droite avec le nom du port ; à côté de chaque pin, l'échange et la fonction distante (plusieurs échanges sur un même pin : listés les uns sous les autres, centrés sur le pin). Clic sur la fonction distante : affiche son bloc (changement de page et filtres relâchés si besoin), ↩ Revenir ramène au bloc de départ ; clic sur le titre d'un bloc : panneau de détail. Pin pâle : port non connecté ; pin en pointillés : échange relié directement à la fonction, sans port (cas normal des activités OA). Option « avec ports ou échanges » (décochée par défaut) pour masquer les fonctions mères.
≡ Vue LigneFonction source, pin de sortie ▶ et port → échange → pin d'entrée ▶ et port, fonction cible ; Exchange Items (▤), Component Exchanges qui l'allouent (🔀), chaînes (⚡).
▣ Vue FonctionUne carte par fonction : échanges reçus (←) et émis (→).
▦ MatriceFonction × fonction (ligne = source, colonne = cible), limitée à 100 fonctions pour rester fluide (les plus connectées) ; filtrez par couche ou fonction pour voir les autres.

Les vues Ligne, Fonction et Blocs sont paginées par 100 (◀ ▶) pour rester fluides sur les modèles de plusieurs milliers de fonctions ; les exports CSV et HTML portent sur tout le résultat filtré.

🎬 Scénarios

Diagrammes de séquence des scénarios Capella — ES (Exchange Scenario), FS (Functional Scenario), OES / OAS en OA, IS (Interface Scenario) — redessinés à partir du seul fichier .capella. À gauche, la liste rangée par couche puis par capacité (filtres couche, type, recherche) ; à droite, le diagramme : lignes de vie (bleu clair = acteur, bleu = composant, vert = fonction, gris = entité), messages avec, pour les ES, leur contexte d'échange entre accolades, barres d'activation, fonctions (rectangles verts), états (ellipses gris clair) et modes (gris foncé), fragments combinés (ALT, OPT, LOOP, PAR…) avec leurs gardes, références « ref » vers un autre scénario (clic : l'ouvrir). Clic sur un élément : son détail. Les noms des lignes de vie restent visibles en haut quand on fait défiler ; défilement par les barres, la molette (Maj + molette : horizontal) ou en cliquant-glissant sur le fond du diagramme. Zoom − / +, exports PNG / SVG et copie de l'image. 🩺 Contrôles : scénarios vides, messages sans échange, lignes de vie sans élément représenté, scénarios hors capacité, références introuvables. Le panneau de détail d'un scénario ou d'une capacité propose aussi 🎬 pour ouvrir le diagramme.

L'ordre des événements est celui du modèle ; les espacements sont calculés (la mise en page dessinée dans Capella est dans le fichier .aird, non lu) : le contenu est fidèle, pas la position au pixel près.

🟨 Operational Analysis

Aussi ≡ Vue Ligne, ▣ Vue Activité, ▦ Matrice activité × activité et 🩺 Contrôles. Filtres : activité, interaction ou Exchange Item, allocation (🏢 Entités, 👤 Acteurs, non allouées, ou une entité / un acteur précis). Exports CSV des interactions et rapports HTML.

🔀 Behavior Exchange (anciennement Component Exchange)

Périmètre : Component Exchanges de la couche PA dont les deux extrémités sont des Physical Components Behavior (aucun Node). Le nombre retenu sur le total du modèle est rappelé en haut de la vue.

Périmètre : échanges entre Physical Components Behavior, et entre un Behavior et un acteur (nœud le plus souvent) qui lui est relié ; ces acteurs apparaissent avec leurs seuls ports concernés.

◧ Vue Blocs (par défaut) : les Physical Components Behavior dessinés comme dans 🧱 Logical Component (bleu = système, bleu clair = acteur ; ports UNSET / IN / OUT / INOUT ; échanges et composants distants cliquables ; fonctions allouées dépliables). Les autres vues (Ligne, Composant, Matrice, Contrôles) sont inchangées.

Orientation des ComponentPort : UNSET (attribut absent) · IN · OUT · ⇄ INOUT. Le sens réel est déduit des deux ports :

→ Orienté / ← InverséUn port IN ou OUT impose le sens (source → cible ou l'inverse).
⇄ BidirectionnelPort(s) INOUT sans autre contrainte.
? Non orientéDeux ports UNSET : sens inconnu (trait pointillé).
⚠ IncohérentOUT→OUT ou IN→IN — sauf pour une DELEGATION, où le sens est déduit de l'imbrication parent / enfant.

Chaque exchange affiche son kind (ASSEMBLY, DELEGATION, FLOW), ses FE alloués (ƒ), ses Exchange Items (▤) et ses Physical Links porteurs (🔌). Contrôles : CE sans FE, ports orphelins, orientations incohérentes, CE non orientés, CE de couche PA non alloués à un lien physique.

🔌 Physical Link

Liens entre composants physiques (et acteurs) via leurs PhysicalPort. Pour chaque lien : les Component Exchanges alloués (⇢) et, sur chaque port, un badge n CP indiquant les Component Ports alloués. Dans les cartouches (ici comme dans 🔀 Component Exchange), les listes longues sont repliées après 4 éléments : cliquez +N autres pour les déplier. Filtres avec / sans CE. Contrôles : liens sans CE, ports physiques non reliés ou sans Component Port, CE de couche PA non alloués.

◧ Vue Blocs (par défaut) : chaque nœud (Physical Component Node) dessiné comme dans Capella : jaune pour un nœud du système, bleu clair pour un nœud acteur ; ports physiques en carré jaune ; à côté de chaque port, le Physical Link (⇄) et le nœud distant, cliquable pour aller à son bloc. Filtres Nature (🖥 Nœuds, 👤 Acteurs) et sous-composants.

🧩 Ports

Traçabilité Function Port ↔ Component Port ↔ Physical Port, reconstruite à partir des PortAllocation et ComponentPortAllocation.

≡ TraçabilitéUne ligne par Function Port / Component Port avec FE, CE, ports physiques et liens. Filtres couche, texte, « chaînes incomplètes ». Export CSV.
▣ Par composantPorts physiques → Component Ports portés ; Component Ports ← Function Ports alloués.
🩺 ContrôlesPorts non alloués à chaque niveau ; sens incohérent entre port de fonction et port de composant ; alignement FE ↔ CE (les ports du FE doivent être alloués aux ports du CE qui le porte) et CE ↔ PL (idem avec les ports physiques). Les délégations sont suivies de proche en proche.

ƒ Fonctions et 🔬 Analyses

Les résultats sont gardés en mémoire ; ↻ Recalculer les rafraîchit. Les contrôles ne sont calculés qu'à l'ouverture de l'onglet 🩺 Contrôles.

Tableaux : sous chaque en-tête, un champ Filtrer… par colonne (plusieurs mots : tous requis ; !mot : exclure) ; le nombre de lignes affichées s'affiche au-dessus, avec ✕ effacer. Analyses transverses calculées à partir de ce que contient le modèle ouvert : une rubrique absente du modèle (pas de machine à états, pas de capacités…) est simplement signalée comme vide, et les contrôles ne portent que sur les pratiques réellement utilisées. Les onglets et les commandes de chaque sous-vue sont entourés par catégorie (vues, filtres, exports), comme dans ƒ Fonctions.

🧪 Cas d'usage — revue d'un modèle Capella

  1. Charger le .capella (glisser-déposer). Consulter 🧭 Explorateur › 📖 Index des types pour voir la composition du modèle.
  2. Parcourir avec 🧭 Explorateur (▦ Cartes et 🌳 Arborescence) ; ouvrir le panneau de détail pour suivre les références entrantes et sortantes.
  3. Analyser un voisinage dans 🗺 Relation Map : choisir un composant dans l'arborescence, régler profondeur, disposition et critères.
  4. Revoir les chaînes dans ⚡ Chaînes : entrées/sorties, fonctions non allouées (gris), échanges sans CE porteur.
  5. Contrôler les interfaces : 🧱 System / Logical Component (blocs à ports façon Capella, ports orphelins ou non orientés), 🔀 Behavior Exchange (PA), ƒ⇆ Functional Exchange (fonctions en blocs à pins façon Capella, ports orphelins, échanges sans Exchange Item), 🔌 Physical Link (liens sans CE), 🧩 Ports (alignement FE ↔ CE ↔ PL).
  6. Mesurer la maturité dans 🔬 Analyses : couverture de traçabilité entre couches, capacités non couvertes, machines à états incomplètes ; comparer avec la version précédente du modèle (⚖ rapport 📰 Notes de version ou 🔍 Revue, à copier dans Word ou Outlook) pour préparer une revue.
  7. Produire un livrable : PDF des chaînes avec annexes, CSV des contrôles et des tables, rapports HTML ; ou 💾 Page HTML pour partager toute l'analyse.
